# ADR-0011: каноническая структура Data и Collector

## Status

Accepted

## Scope

`cybercity-data`, `cybercity-collector`.

## Context

`cybercity-data` экспортирует часть API из корневого Python-пакета, а
`cybercity-collector` организован как Cargo workspace из публичных crates
`ccc-*`. Текущая методология требует один канонический модуль сервиса и одну
точку сборки зависимостей. Человек явно выбрал перестройку репозиториев под этот
канон вместо расширения методологии.

## Decision

- Data переходит на явные импорты из канонического модуля; корневые re-export
  удаляются, потребители и тесты мигрируют на новые пути.
- Collector становится одним Rust package; прежние crates превращаются во
  внутренние модули, а `ccc-node` остаётся единственным исполняемым поведением.
- Несовместимость публичных Python-импортов и Rust crate API фиксируется как
  `BREAKING CHANGE:`. Форматы событий, конфигурации и сетевое поведение не меняются.

## Consequences

- Репозитории проходят единый структурный `VER-015` без специальных исключений.
- Внешним потребителям прежних импортов и crates требуется миграция.
- Один package упрощает сборку Collector, но исключает независимое
  версионирование `ccc-*`.

## Alternatives considered

- Расширить verifier безопасными Python re-export и Rust workspace-профилем —
  отвергнуто явным решением человека.
- Скрыть несовместимость import-hook или фиктивными обёртками — отвергнуто как
  обход обязательной проверки.
